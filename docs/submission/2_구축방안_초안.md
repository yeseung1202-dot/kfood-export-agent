■ 전체 구조
수집(collect.py) → 점수화·검증(score.py) → 근거 리포트(report.py) → 데모 화면(app.py, Streamlit)의 4단계 파이프라인입니다. 각 단계는 파일(CSV·JSON)로만 연결되어 따로 실행하고 검증할 수 있고, 모든 단계를 코드로 재현할 수 있습니다.

■ 1. 데이터 수집과 검증 (collect.py)
· 관세청 품목별·국가별 수출입실적 API: 37개국 × 7개 기간 × 4개 HS, 1,036회 호출. 응답의 월별 행 합계가 '총계' 행과 일치하는지 표본 대조해 중복 합산·누락이 없음을 확인했습니다.
· UN Comtrade: 각국의 제과류 수입액과 한국·일본·중국 점유율. 국가마다 보고가 늦은 점을 감안해 국가별 최신 보고연도를 따로 기록합니다.
· World Bank·IMF: 인구구조·도시화·1인당 GDP·성장률 전망. IMF API가 긴 요청 URL을 거부하는 문제를 발견해 전체 수신 후 필터링하도록 고쳤습니다.
· 원자료는 data/raw에 캐시하고 수집 시각·URL·오류를 로그로 남깁니다.

■ 2. 점수화 (score.py)
· 지표 정의를 코드 상단 표 하나(열·축·방향·출처·기준연도)로 관리해 지표를 추가할 때 한 줄만 고치면 됩니다.
· 지표별 백분위(0~100) → 축 점수 → 가중평균. 단위가 다른 지표를 공정하게 합치고 극단값의 영향을 줄입니다.
· 결측 처리: 0점으로 채우지 않고, 값이 있는 지표 비율만큼만 반영하고 나머지는 중립(50)으로 둡니다. 실제로 Pepero 지표 하나만 있던 몽골이 트렌드 100점으로 1위가 되는 왜곡을 발견해 도입했습니다.
· 두 트랙: 2025년 한국 제과 수출 2,000만 달러 이상 9개국은 '기존 주력 확대형', 나머지는 '신규 개척형'으로 따로 순위를 매깁니다. 검색 관심도·수출 증가율이 이미 진출한 시장에 유리해, 섞으면 '발굴'이 아니라 '기존 시장 재확인'이 되기 때문입니다. 싱가포르·네덜란드처럼 재수출 허브인 나라는 표시를 붙입니다.
· 데이터 품질 규칙: 기준 수출액 10만 달러 미만의 증가율은 결측 처리(작은 기저 왜곡 방지), 일본 점유율 0.5% 미만이면 '여백' 지표를 쓰지 않음(수요 미검증 시장 과대평가 방지).
· 2단계 실행가능성: 같은 함수를 재사용해 최종 = 0.7×과제 3축 + 0.3×실행가능성으로 결합합니다. 관세는 WITS 공식 세율에 FTA 발효 여부를 반영했고, 확인되지 않은 FTA 세율은 MFN을 보수적으로 적용하고 표시했습니다.

■ 3. 안정성 검증
몬테카를로 2,000회: 축 가중치(Dirichlet 분포), 실행가능성 비중(0.1~0.5), 지표 1개 무작위 제외를 동시에 흔들어 국가별 TOP3 진입률을 계산합니다. 신규 개척형 1위 싱가포르는 98%로 안정적이고, 공동 2위 영국·네덜란드는 50~60%대라 결과와 함께 "경합"이라고 정직하게 보고합니다. 불확실한 입력값(필리핀 FTA 세율, 할랄 부담)은 바꿔 넣어도 TOP3가 유지되는지 시나리오로 확인했습니다.

■ 4. AI 활용과 환각 방지 (report.py)
· 점수 계산은 LLM에 맡기지 않고 코드로 수행합니다. 같은 입력이면 같은 결과가 나와야 심사·현업 검증이 가능하기 때문입니다.
· LLM(HyperCLOVA X HCX-007)은 score.py가 만든 '근거 목록'만 받아 문장을 씁니다. OpenAI 호환 API로 연결해 설정 한 줄로 OpenAI 모델로도 바꿀 수 있습니다.
· "LLM은 문장만, 숫자는 코드가": LLM은 숫자 자리에 근거 번호 {n}만 쓰고, 코드가 근거 값을 넣습니다. 초기에는 LLM이 숫자를 직접 써서 반올림(20.0%→20%), 다른 지표 값 끌어오기, 값 2.0을 '2위'로 쓰기가 반복됐고, 이 구조로 숫자 오류를 원천 차단했습니다.
· 작성 → 같은 LLM의 검토(근거와 모순·과장 수정) → 숫자 대조(자리표시 밖 숫자, 붙여 쓴 자리표시, 잘린 응답이면 재생성, 최대 3회)를 거치고, 마지막으로 사람이 해석 오류를 고쳐 검토 수정본을 남깁니다(이번 TOP3에서 지표 이름 뒤바뀜 등 6곳). API 키가 없으면 템플릿으로 작성해 시스템이 멈추지 않습니다.
· 테스트 13개(방향 반전, 결측 처리, 탈락 규칙, 트랙 분리, 재현성, 환각 숫자·순위 검출, LLM 메타 줄 정리 등)를 자동으로 점검합니다.

■ 5. 한계와 대응
· Google Trends는 소국 데이터가 없어, 싱가포르를 기준으로 한 지역 비교로 환산하고 '환산값'으로 표시했습니다.
· 리드타임은 공개 항로거리 ÷ 14노트로 통일해 계산했고, 항만 대기와 통관 시간은 본선 현장 데이터로 보정할 계획입니다.
· 내부 데이터 슬롯: data/internal/internal.csv가 있으면 롯데 국가별 영업이익률이 실행가능성 지표로 자동 반영됩니다. 예선에서는 가상 샘플로만 시연하고 화면에 명시했습니다.

■ 6. 본선 1박2일 확장 계획
