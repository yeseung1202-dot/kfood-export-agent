■ AI 모델 설계
"계산과 대조는 코드, 문장은 AI, 최종 판단은 사람"으로 역할을 나눴습니다.
· 점수 계산은 LLM에 맡기지 않고 코드로 수행합니다. 같은 입력이면 같은 결과가 나와야 심사와 현업이 검증할 수 있기 때문입니다.
· 1단계(과제 3축): 지표별 백분위(0~100) → 축 점수 → 가중평균(각 1/3). 단위가 다른 지표를 공정하게 합치고 극단값의 영향을 줄입니다. 시장 규모는 점수가 아닌 최소 기준(제과 수입시장 5천만 달러)으로만 써서 성장 여력이 큰 나라를 찾습니다.
· 탈락 조건: 롯데가 이미 현지 공장을 운영하는 인도·카자흐스탄·러시아·파키스탄은 수출 대상이 아니므로 제외하고, 일본(원롯데 홈마켓)·미얀마(내전)도 사유를 남기고 뺍니다.
· '일본 대비 한국 점유율 여백'은 일본 점유율이 0.5% 이상인 나라에서만 계산해, 아시아 과자 수요가 확인된 시장의 빈자리만 기회로 봅니다.
· 2단계(롯데 실행가능성): 1단계 TOP10에만 적용하며, 최종 점수 = 0.7×과제 3축 + 0.3×실행가능성입니다.
· LLM(HyperCLOVA X HCX-007)은 코드가 만든 '근거 목록'만 받아 국가별 추천 문장을 씁니다. OpenAI 호환 API로 연결해 설정 한 줄로 OpenAI 모델로도 바꿀 수 있습니다.

■ 활용 데이터
· 관세청 품목별·국가별 수출입실적 API: 37개국 × 7개 기간 × 4개 HS, 1,036회 호출
· UN Comtrade: 각국 제과 수입액과 한국·일본·중국 점유율(국가별 최신 보고연도 기록)
· World Bank: 0~14세 인구 비중, 도시화율, 물류성과지수(LPI) / IMF WEO: 1인당 GDP, 2026~2030 성장 전망
· Google Trends: '한국 요리'(주제), 'korean snack', 'Pepero', 'K-pop' 국가별 관심도
· 실행가능성: 항로거리 기반 리드타임(중동은 인도 빼빼로 공장, 우즈베키스탄은 카자흐 공장 출발), WITS 관세와 FTA, 할랄, 과자 열량세, OECD 국가위험등급
· 콜드체인은 국가 간 비교 가능한 공식 지표가 없어 LPI로 대체했습니다.

■ AI 에이전트 개발 방식
수집(collect.py) → 점수화·검증(score.py) → 근거 리포트(report.py) → 데모(app.py, Streamlit)의 4단계 파이프라인입니다. 단계 사이는 파일로만 연결돼 각각 실행하고 검증할 수 있습니다.
· 지표 정의를 코드 상단 표 하나(열·축·방향·출처·기준연도)로 관리해, 지표를 추가할 때 한 줄만 고치면 됩니다.
· 국가마다 점수를 올린·깎은 지표 상위 3개를 원값·백분위·출처·기준연도와 함께 뽑아 근거 목록을 만들고, 리포트와 데모는 이 목록만 씁니다.
· 리포트 생성은 작성 → 같은 LLM의 근거 대조 검토 → 코드 숫자 검사(최대 3회 재생성) → 사람의 최종 검토 순서입니다. 이번 TOP3에서는 숫자만 나열한 문장, 근거 없는 표현 등 5곳을 고쳤고, 숫자 수정은 0건이었습니다. 응답이 비거나 토큰 한도로 잘리면 다시 요청하고, 호출이 모두 실패하면 템플릿 문장으로 대체해 파이프라인이 멈추지 않습니다.
· 데모 화면에서 트랙을 고르고 가중치를 슬라이더로 바꾸면 즉시 재계산되며, 근거·출처·안정성·탈락국 사유를 함께 보여줍니다. 같은 계산식을 브라우저로 옮긴 웹 데모로 공개해 설치 없이 열 수 있고, Python 결과와 값이 같은지 자동으로 대조합니다.
· 롯데 내부 데이터 슬롯: 국가별 영업이익률 파일을 넣으면 실행가능성 지표로 자동 반영되며, 이 파일은 공개 저장소에 올라가지 않게 막아 두었습니다.
· Claude Code로 설계·구현·테스트를 진행하고, 작업 규칙을 문서로 관리했습니다.

■ 신뢰성·안정성 확보 방안
1) 숫자 환각 차단: 초기에는 LLM이 숫자를 직접 쓰면서 반올림(20.0%→20%), 다른 지표 값 끌어오기, 값 2.0을 '2위'로 쓰기가 반복됐습니다. 그래서 LLM은 숫자 자리에 근거 번호만 쓰고, 코드가 값을 넣도록 바꿨습니다. 근거마다 강점/약점을 표시해 약점을 장점으로 뒤집어 쓰는 오류도 막습니다.
2) 결과 안정성: 몬테카를로 2,000회로 축 가중치, 실행가능성 비중(0.1~0.5), 지표 1개 제외를 동시에 흔들어 TOP3 유지율을 계산합니다. 가중치는 디리클레 분포로 뽑고 시드를 고정해 같은 결과가 재현되며, 유지율 70% 이상만 '안정'으로 표시합니다. 싱가포르 98%·영국 86%는 안정, 네덜란드 58%는 경합으로 보고합니다.
3) 데이터 품질 규칙
· 결측은 0점이 아니라 중립(50)으로 둡니다. 'Pepero' 지표 하나만 있던 몽골이 트렌드 1위가 되는 왜곡을 발견해 도입했습니다. 유효 지표가 절반 미만인 축은 '데이터 부족'으로 표시합니다.
· 기준 수출액 10만 달러 미만의 증가율은 쓰지 않아 작은 기저의 왜곡을 막습니다.
· 관세청 월별 합계와 '총계' 행을 표본 대조해 중복과 누락이 없음을 확인했습니다.
· 실행가능성 표는 항목마다 출처 열을 두고, 수동 입력 표에 후보 목록에 없는 국가명이 있으면 오타로 보고 경고합니다.
4) 테스트 13개: 방향 반전, 결측, 탈락 규칙, 트랙 분리, 재현성, 환각 숫자 검출을 자동으로 점검합니다.
5) 한계 공개: 싱가포르·네덜란드는 재수출 허브라 수입액이 실제 소비보다 클 수 있고, 영어 검색어는 비영어권을 과소평가할 수 있습니다. 리드타임은 항로거리 ÷ 14노트로 계산해 항만 대기는 제외했고, 유럽은 벨기에 길리안 공장을 출발지로 넣지 않고 부산 기준으로 보수 계산했습니다. 각 한계는 화면과 리포트에 표시합니다.
